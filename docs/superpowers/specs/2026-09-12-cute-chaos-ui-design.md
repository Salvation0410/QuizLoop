# Quizeloop 可爱搞怪篇 UI 原型设计

## 1. 目标与范围

本设计用于指导 Quizeloop AI 闯关学习小程序的 HTML 视觉原型。目标是把“输入知识 -> AI 出题 -> 闯关答题 -> 即时讲解 -> 复盘报告”的 MVP 闭环，转译为具有漫画节奏、轻松鼓励氛围的界面草图。

本阶段只交付静态 HTML/CSS/少量原型交互，不接入真实 AI、微信登录、联网搜索或后端服务。页面按核心业务流程与扩展功能拆分为独立 HTML 文件，每个文件展示三张同类页面卡片，并支持窄屏响应式换行。

## 2. 视觉方向

- **关键词：** 可爱、搞怪、轻吐槽、可信学习、即时奖励。
- **构图：** 奶油纸张作为画布，内容以白色便签卡片承载；卡片使用粗黑描边、硬阴影和轻微歪斜，模拟漫画分镜与手帐贴纸。
- **色彩：** 墨黑 `#22212B` 为文字与描边；奶油 `#FFF8E8` 为底色；珊瑚红、阳光黄、天空蓝、青柠绿、糖果粉用于状态与奖励。避免大面积渐变，保证题目文字对比度。
- **字体：** 标题采用有漫画感的衬线字体，正文使用系统无衬线字体；不依赖外部字体资源，保证原型离线可打开。
- **角色：** 使用原创占位表情与几何头像，不直接使用《漫画阿衰》人物、台词或受版权保护的图像。角色状态至少覆盖得意、震惊、挠头、击掌四种语义。
- **文案：** 允许夸张和双关，但不得嘲讽用户；答错反馈必须同时给出正确知识与下一步动作。

## 3. 页面分组

### 3.1 核心流程原型（建议文件：`core-flow.html`）

三列按用户路径排列：

1. **输入页：** 一个醒目的主题/文本输入区，示例提示词，题量选择，主按钮“开始生成”。
2. **生成中 / 闯关页：** 展示 AI 生成状态后进入题目卡；包含关卡进度、XP、金币、题干、选项和角色吐槽气泡。
3. **答题反馈 / 报告页：** 同屏表现答对与答错反馈、知识讲解、奖励变化，并提供通关后的正确率、掌握度、知识总结和分享海报入口。

原型交互：点击输入示例可填充内容；点击选项显示选中态；点击提交切换讲解态；点击下一题更新进度；报告页按钮显示分享海报占位层。

### 3.2 扩展功能原型（建议文件：`feature-extensions.html`）

三列按后续优先级排列：

1. **错题本与复习：** 错题列表、知识点标签、遗忘曲线提醒、重新闯关入口。
2. **知识库与学习分析：** 私有资料夹、主题掌握度、正确率趋势、薄弱知识点和报告生成入口。
3. **社交 PK 与排行榜：** 好友挑战卡、倒计时状态、领域榜单、个人排名和分享邀请入口。

扩展页统一沿用核心视觉令牌，但密度更接近微信小程序后台：信息优先、卡片不过度装饰、移动端单列阅读。

## 4. 组件与状态约定

- **进度：** 以圆点路径和当前题号表达，不使用复杂图表替代关键数字。
- **奖励：** XP 使用闪电符号，金币使用圆形徽章；奖励出现时使用高亮贴纸或短暂缩放动画。
- **反馈：** 正确为青柠绿背景，错误为珊瑚/粉色提示；两者都必须展示解释文本。
- **按钮：** 主动作使用高对比实心按钮，次动作使用描边按钮；按钮文案保持动词开头。
- **可访问性：** 文本与背景保持清晰对比；状态不只依赖颜色，同时配合图标或文字；窄屏不出现横向滚动。

## 5. 交付与验收

交付至少包含 `core-flow.html` 与 `feature-extensions.html`，并保留视觉方向板 `cute-chaos-v2.html` 作为参考。验收标准：

1. 桌面端每个文件首屏能同时看到三列页面卡片。
2. 视口宽度低于 820px 时自动换为单列或双列，内容不重叠。
3. 核心答题路径具备可点击的选中、提交、讲解、下一题和报告入口状态切换。
4. 所有图形均由 CSS/文字/原创占位元素构成，不引入《漫画阿衰》原作素材。
5. 视觉风格与已确认的可爱搞怪方向一致，同时保留学习产品的可信度和信息层级。
